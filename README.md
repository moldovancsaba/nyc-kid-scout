# Class Scout NY

**Repository:** `nyc-kid-scout` · **UI names:** Class Scout NY / Class Scout NYC

A demonstration web app for exploring NYC kids' classes, camps, birthday parties, drop-in activities, family events and meet-up groups. It includes saved providers, an activity-cost calculator and an optional connected AI assistant.

The catalog and prices are demo data. Provider names, addresses, contacts, ratings and review counts generated by this repository are not a verified directory. Event availability, bookings and real-world provider identity have not been established.

## What works in this source

| Surface | Implemented boundary |
| --- | --- |
| Discover | Browse/filter bundled provider data and open detail/share panels |
| Saved | Persist selected provider IDs in this browser's local storage |
| Calculator | Persist provider IDs/class counts and calculate totals from demo prices |
| Family events and meet-ups | Browse bundled fixture data |
| My Account | Demo/sample sections and component-local preference controls; no implemented sign-in flow in the app routes |
| Checkout | Validate basic form fields and switch to a confirmation screen in memory |
| AI assistant | Send chat history and a provider-data payload to a separately deployed edge function; render streamed replies and matching provider cards |

Checkout does **not** create a reservation, charge a payment or send a confirmation email. Its screen says a confirmation was sent, but the inspected handler only changes React state. Treat it as a UI simulation.

The account page can show sample saved items when none exist. Its preference/email-settings “saved” messages are UI notifications, not proof of backend persistence or email delivery. Notifications and cross-device account synchronization are not established capabilities.

Navigation between the main app views uses component state on the root route. Those views are not separate addressable routes.

## Local setup

The existing application uses Vite, React and TypeScript. **Clean installation on the current default branch is blocked:** its npm lockfile is out of sync with the manifest. [Draft repair PR #1](https://github.com/moldovancsaba/nyc-kid-scout/pull/1) restores installation in a disposable check, but remains unmerged because dependency/lint findings need review. Track that work in [issue #2](https://github.com/moldovancsaba/nyc-kid-scout/issues/2).

The commands below describe the repository's intended workflow after that install blocker is resolved; they are not a claim that the default branch currently installs cleanly.

Use Node.js 24 and the npm lockfile. From the repository root:

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

The configured development port is 8080; use the URL printed by Vite if that port is occupied. Ctrl-C stops the server. The loopback override avoids the configuration's default all-interface bind.

Build and inspect the static output:

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

Preview serves the generated `dist/` frontend. It does not deploy or run the Supabase edge function.

## Optional assistant configuration

The assistant client reads these build-time variables:

| Variable | Role |
| --- | --- |
| `VITE_SUPABASE_URL` | Base URL used to construct `/functions/v1/scout-assistant` |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Public client key sent in the request's Authorization header |

Put local overrides in an untracked `.env.local` and restart/rebuild after changes. Vite variables are client-visible; they must not contain server secrets.

The separately hosted function reads `LOVABLE_API_KEY` in its server environment and calls Lovable's AI gateway. Keep that credential server-side. The function's current source requests `google/gemini-3-flash-preview` and returns a streamed response; the client handles rate-limit and exhausted-credit responses.

Live AI operation requires the edge function, valid server/client configuration and service availability/credits. Building or previewing this repository alone does not provision that service. The client sends the conversation and bundled provider summaries to it. Use synthetic prompts for investigation; no live AI request is part of this welcome repair's verification.

## Data, recovery and verification limits

Saved provider IDs use local-storage key `csny.saved`; calculator items use `csny.calc`. They belong to the current browser origin and are not a cloud account. Removing those keys in browser developer tools resets that local state. Preserve anything needed before clearing it; this app has no export/restore contract.

Checkout and account preference state are component-local and can reset when the view unmounts or the page reloads. Chat history is component state, not a documented durable conversation store.

`npm run lint` runs ESLint. `npm test` runs Vitest, but the checked-in test is an example asserting `true`; it does not verify app workflows. The [delivery issue](https://github.com/moldovancsaba/mvp-factory-control/issues/927) records exact command outcomes. On 19 October 2026, the candidate lockfile passed install/build/static preview, while lint reported 4 errors and 8 warnings and npm reported 37 advisories (including 2 critical). The default-branch install failure and these candidate baseline findings remain open in [issue #2](https://github.com/moldovancsaba/nyc-kid-scout/issues/2). A static server response is not an end-to-end booking, account or AI acceptance test.
